# Audio Context Layer

**A LoRA-adapted Qwen2-Audio-7B-Instruct system for audio-grounded question answering, evaluated on the DCASE 2025 Task 5 (Audio Question Answering, Part 1) benchmark.**

📄 **Full technical report:** [`docs/Audio_Context_Layer_Final_Report.pdf`](docs/Audio_Context_Layer_Final_Report.pdf) ([source](docs/final_report.md))

## Objective

Given an audio recording and a natural-language, multiple-choice question about it, produce the answer best supported by the audio's content. The system is built by adapting a pretrained audio-language model with parameter-efficient fine-tuning (LoRA) rather than training from scratch.

## Dataset

DCASE 2025 Task 5, Audio Question Answering, Part 1. Prepared, leakage-remediated manifests (see the final report, Sections 3–8, for full construction and validation methodology):

| Split | Records | Unique audio |
|---|---:|---:|
| Train | 1,436 | 1,436 |
| Validation | 158 | 158 |
| Test | 2,466 | 2,415 |

Question types actually present in the data: `sound detection`, `sound counting`, `audio tagging`, `apply_duration`, `apply_frequency`, `understand_acoustics`, `remember`, `species`, `vocalization`, `both`, `audio detection`.

## Architecture & Methodology

```
Audio + Question + Choices
        |
   Qwen2-Audio (pretrained)
        |
   LoRA adaptation (language_model.* only)
        |
   Answer generation
        |
   Evaluation (option-label + normalized-text matching)
```

- **Model**: `Qwen/Qwen2-Audio-7B-Instruct` (audio tower + Qwen2 language-model decoder + multimodal projector).
- **Adaptation**: PEFT LoRA (rank 16, alpha 32, dropout 0.05), scoped and validated to the `language_model.*` subtree only, to avoid unintentionally adapting the frozen audio encoder.
- **Training objective**: supervised `audio + question + choices → answer`, with padding and prompt tokens masked out of the loss so only the answer span is supervised.
- **Evaluation**: option-label extraction with a conservative normalized-text fallback — no semantic-similarity matching.

Full architectural and methodological detail, including design-decision justifications, is in the final report.

## Reproducibility

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -e .

python scripts/build_manifests.py       # rebuild manifests from raw metadata
python scripts/validate_splits.py       # leakage / integrity validation
python scripts/validate_audio_integrity.py
python -m unittest discover -s tests    # automated test suite

python scripts/train.py
python scripts/run_inference.py --split test --adapter-dir checkpoints/best
python scripts/evaluate.py --predictions results/predictions/predictions.jsonl
python scripts/generate_report.py       # regenerates the final report + PDF from live results
```

Exact dependency versions are pinned in `requirements.txt`; the full runtime environment (Python/PyTorch/Transformers/PEFT/Accelerate versions, CUDA availability, GPU identification) is recorded automatically at the start of every training run.
